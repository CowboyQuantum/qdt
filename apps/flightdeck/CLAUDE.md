# apps/flightdeck — package rules

Flight Deck is the front end. Restarted from scratch (ADR 0005). TypeScript. Transport and renderer class are decided (ADR 0008): WebSocket + Arrow IPC, WebGL 2D. The 2D renderer is raw WebGL2 with no library (ADR 0013, closing #9); `pnpm bench` reproduces Analysis 0002; in CI `--assert --latency-advisory --rate-advisory` reports both targets and fails only below half the rate (ADR 0039; the targets are evidenced by `bench/results/`). Browser pixel tests: `pnpm build && pnpm test:e2e`.

## Entry gate (ADR 0011)
UI code may be written once `docs/FINISH_LINE.md` is authored (done) and the `Dataset` stream contract is **drafted** in `qdt-schemas` with ADRs (done: ADR 0009, 0010). The contract *freeze* (after Probe 01) gates Step 1's exit, not UI work. Until the freeze:
- consume only the generated types and the wire protocol of ADR 0010; never hand-code around a draft field;
- a contract change regenerates `src/schema/` and must keep every Flight Deck test green in the same commit.

## Rules
- Rule 8: never import an instrument driver; never branch on which instrument produced a `Dataset`. `scripts/check_imports.py` greps for violations. The only permitted read of `dataset.source` is `registry_ref`, to label the view (ADR 0027); `test/render.test.ts` enforces it.
- All data enters through a `Source` implementation (`replay`, `websocket`, later `registry`). A new source must pass the source-equivalence test: the same `Dataset` through any source renders identically.
- Types under `src/schema/` are **generated**: `data.ts` from `packages/qdt-schemas/exports/jsonschema/data.schema.json` (`pnpm gen:types`) and `api.ts` from `packages/qdt-server/exports/openapi.json` (`pnpm gen:api`, ADR 0034); CI fails on drift. Never edit them by hand.
- The control path (Step 4b, ADR 0032): `src/api/client.ts` is the only code that talks to qdt-server, over HTTP, with the generated `api.ts` types; `src/control/` builds schema objects from forms (`sweeps.ts`, `methods.ts`, `sequence.ts` — the pulse-sequence editor model, a form over `PulseSequence` whose columns are type-checked against the generated types, ADR 0035: pure, unit-tested) and wires the panel (`panel.ts`). What is drawn stays a function of the Dataset stream; the panel only asks the server to put things on it.
- Every announced Dataset is kept and selectable (`#datasets`); the newest is shown as it arrives. `e2e/control.test.ts` is the Step 4b exit: it spawns `python -m qdt_server` and drives the panel.
- Transforms (derivative, filter, normalize) are client-side on typed arrays; no server round-trip per toggle. The variable picker and "minus" (a − b of two same-shape variables, ADR 0037) are view options too.
- The workspace (Step 6b, ADR 0054): `main.ts` is wiring only. `src/workspace/layout.ts` is the pure layout model (three columns of panes, plots only in the centre, split/close/resize, persisted per browser under `flightdeck.layout.v1`); `workspace.ts` renders it and reconciles panes by id; `widget.ts` is the widget contract and registry (`mount(body, head, ctx) => unmount`, a bus scoped per mount so a closed pane leaks nothing); `bus.ts` holds every event widgets exchange (add an event there, nowhere else); `strip.ts` is the top strip (stand, device, source, live pill, next run, the one Run, telemetry, messages, replay picker, theme menu). Widgets live in `src/widgets/` and reach the server only through `ctx.api`, the data through `ctx.datasets` (the shared stores, `src/stream/datasets.ts`), each other through `ctx.bus`. `control` is the Step 4b panel mounted unchanged as one temporary widget; later sessions extract its sections into widgets and delete `panel.ts`. `plot` (ADR 0055) is any number of centre panes over the shared stores, each following the stream or pinned to one Dataset, with its own renderer, view options (the ⚙ menu: dataset, variable, minus, transform, swap, cut) and line cut; six at most (`MAX_PLOT_PANES`, one WebGL2 context each; a closed pane disposes its renderer). `history` lists `/records` and opens one in a pane: the server replays it on the stream and the pane pins itself to the Dataset whose `registry_ref` is the record (`plot:open`); panes announce what they show (`plot:view`). `sweep` and `pulse` (ADR 0056) are the sweep form and the pulse-sequence editor over the unchanged pure models: the Sweep widget compiles (`plan:compiled` carries the identity to the strip), any edit marks the plan stale (`plan:changed`), the strip's one Run (`run:request`) makes the Sweep widget compile again if stale and run; it follows the run (`run:state`). The Pulse widget follows the Sweep widget's template (`sweep:axes`) and publishes its sequence (`pulse:sequence`); a stage sweep needs it mounted. The e2e tests address panes by position (`.col.center .pane`, `canvas.map`, `canvas.overlay`, `.menu.plot select[name=…]`, `.pane[data-widget=sweep] …`), never by id, and press the strip's `#run`. `levels` (ADR 0057) is the operating point by channel over `GET /levels/state` (polled): setpoint, held, readback; filters, sort, pins and the limit are per browser; click-to-set lands here (`map:click` → offer → `POST /levels`). `gates` is the coupling matrix per browser; the Sweep widget takes each stepped axis's row as `SweepAxis.couplings` (`gates:couplings`), never a stage inner axis. Themes are data: `themes/*.json` validated against `themes/theme.schema.json` by `workspace/theme.ts` (thirteen `#rrggbb` tokens, type, shape, scheme, a closed list of decoration flags that become `deco-*` classes on `<html>`); a theme can never inject CSS, and `test/theme.test.ts` keeps the schema and the validator in step. Colormaps are view settings, not theme content. `e2e/workspace.test.ts` drives the shell.
- Scope: `replay` (`.qdtrec`) and `websocket` sources (fed by `python -m qdt_lab.stream`, `python -m qdt_registry serve`, or `qdt-server`); 1D trace, 2D heatmap, live update, overlays; from Step 4b the control panel (stage, DC and, from ADR 0047, capture sweeps). The view is chosen from the Dataset's shape (`view.ts`): a variable whose leading dim has no coordinate over one that does is a trace of its latest record; two coordinated dims are a heatmap. Traces draw on the 2-D `#overlay` canvas (the map renderer owns `#plot`'s WebGL context) and show 1-coordinate markers as rules. Click-to-set (ADR 0053, the one "up" edge): a click on the map yields the point under it as coordinate names and values (`view.pointAt`); the panel maps names to the stand's DC channels (`setpointFor`) and posts `/levels`; the view itself never names a channel or an instrument. Real instruments (Step 5) arrive through the same `websocket` source and the same API; nothing in `src/` changes for them.
